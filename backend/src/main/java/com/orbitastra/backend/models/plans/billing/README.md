# SaaS subscription billing model mapping

These models are reserved for payment-gateway integration. They bill schools for
the SaaS platform subscription; they are not student fee-payment models.

## Relationship overview

```text
SchoolSubscription
  |
  +--> SubscriptionInvoice
          |
          +--> SubscriptionPayment
          |
          +--> PaymentAttempt
                   |
                   +--> SubscriptionPayment (when an aggregate exists)

Payment provider
  |
  +--> BillingWebhookEvent
          |
          +--> invoice / payment / attempt / subscription
```

Every collection extends SchoolBase and must be queried with `schoolId`.

## SubscriptionInvoice — `subscription_invoices`

Financial invoice issued for one subscription billing period.

| Field | Meaning and mapping |
|---|---|
| `invoiceNo` | School-scoped business number generated by NumberSequence. |
| `schoolSubscriptionDocsId` | Link to SchoolSubscription.id. |
| `billingPeriodStart/end` | Contracted service period being billed. |
| `issueDate` | Legal issue date. |
| `dueDate` | Payment deadline. |
| `status` | Invoice financial lifecycle. |
| `currencyCode` | Currency applying to every amount. |
| `subTotal` | Amount before tax. |
| `taxAmount` | Tax total. |
| `totalAmount` | Final invoice total. |
| `paidAmount` | Successfully allocated payment total. |
| `outstandingAmount` | Remaining unpaid amount. |
| `gatewayInvoiceReference` | Optional provider invoice id. |
| `paidAt` | Time the outstanding amount reached zero. |
| `issuedAt` | Actual issue timestamp. |
| `voidedAt` / `voidReason` | Audit-preserving invoice cancellation. |

The business invariant is:

```text
totalAmount = subTotal + taxAmount
outstandingAmount = totalAmount - paidAmount
```

The billing service enforces it transactionally. Issued invoices are never
physically deleted or silently rewritten.

## SubscriptionPayment — `subscription_payments`

Represents a payment aggregate against one subscription invoice.

| Field | Meaning and mapping |
|---|---|
| `paymentNo` | School-scoped NumberSequence value. |
| `schoolSubscriptionDocsId` | Link to SchoolSubscription.id. |
| `subscriptionInvoiceDocsId` | Link to SubscriptionInvoice.id. |
| `status` | Payment lifecycle. |
| `paymentMethod` | UPI, card, transfer, cash, or another supported method. |
| `amount` / `currencyCode` | Received or attempted amount and currency. |
| `gatewayProvider` | Provider code; optional for offline payments. |
| `gatewayPaymentReference` | Provider payment id. |
| `gatewayOrderReference` | Provider order id. |
| `settlementReference` | Provider/bank settlement id. |
| `receivedAt` | Successful receipt time. |
| `settledAt` | Settlement time. |
| `failureReason` | Aggregate failure explanation. |

Provider payment references are globally unique within one provider. Payment
numbers are unique within one school.

## PaymentAttempt — `subscription_payment_attempts`

Stores every gateway attempt, including failures and customer-action states.

| Field | Meaning and mapping |
|---|---|
| `subscriptionInvoiceDocsId` | Link to SubscriptionInvoice.id. |
| `subscriptionPaymentDocsId` | Optional link to the resulting SubscriptionPayment. |
| `attemptNo` | Retry number within the invoice. |
| `status` | Provider-processing state. |
| `paymentMethod` | Attempted payment method. |
| `amount` / `currencyCode` | Attempt amount and currency. |
| `gatewayProvider` | Provider code. |
| `idempotencyKey` | Unique provider-operation key. |
| `gatewayAttemptReference` | Provider attempt/payment id. |
| `failureCode` / `failureMessage` | Provider error details. |
| `attemptedAt` / `completedAt` | Attempt timing. |

The integration must reuse the same idempotency key when retrying the same
logical provider request.

## BillingWebhookEvent — `billing_webhook_events`

Durably records one provider webhook before applying its business effect.

| Field | Meaning and mapping |
|---|---|
| `gatewayProvider` | Provider code. |
| `providerEventId` | Provider's immutable event id. |
| `providerEventType` | Provider event type. |
| `processingStatus` | Internal receipt/verification/processing state. |
| `signatureValid` | Result of signature verification. |
| `payloadHash` | Integrity/deduplication hash. |
| `encryptedPayload` | Encrypted raw payload for audit/reprocessing. |
| `relatedEntityType` | Type such as invoice, payment, attempt, or subscription. |
| `relatedEntityDocsId` | Resolved related document id. |
| `processingAttemptCount` | Internal retry counter. |
| `receivedAt` / `processedAt` | Webhook timing. |
| `nextRetryAt` | Scheduled retry time. |
| `failureCode` / `failureMessage` | Processing error details. |

`gatewayProvider + providerEventId` is unique, making webhook delivery
idempotent. A webhook must be authenticated and mapped to a School tenant before
this SchoolBase document is persisted.

## Transaction boundaries

A successful payment normally updates:

1. PaymentAttempt;
2. SubscriptionPayment;
3. SubscriptionInvoice paid and outstanding amounts;
4. SchoolSubscription status when recovering from past due;
5. SubscriptionHistory.

These changes must be idempotent and committed using an appropriate MongoDB
transaction or a durable event/outbox workflow.

## Validation responsibility

The models retain only essential required identifiers, statuses, dates,
currencies, amounts, provider keys, and webhook audit fields.

Request DTOs, gateway adapters, and billing services validate:

- positive amounts and supported currencies;
- invoice total equations and date ordering;
- payment/invoice currency equality;
- legal status transitions;
- gateway signatures and provider payload schemas;
- conditional fields for online/offline methods;
- refund and settlement rules;
- idempotency and tenant ownership;
- encrypted-payload retention and access control.
